# 仕訳トレーニング PWA

GitHub Pagesにそのまま配置できる、スマートフォン向けの独立したPWAです。ビルド不要。アプリの実行にnpm・サーバー処理・外部API・CDNは不要です。

**簿記2級70問＋税理士簿記論230問、計300問を収録。** 初回オンラインで必要ファイルを保存すると、問題・電卓・採点・解説・学習記録・復習をオフラインで利用できる構成です。ChatGPT Sitesは使用していません。

## まず公開して使う

1. ZIPを展開する。
2. `shiwake-training`フォルダー**の中身**をGitHubリポジトリのルートへアップロードする。
3. Settings → Pages → Deploy from a branch → `main` / `/(root)` → Save。
4. 公開されたURLをiPhoneのSafariで開く。
5. 「オフライン準備完了」を確認して「ホーム画面に追加」。

公開・実機確認は利用者側で行います。詳細は以下を参照してください。

## 1. ローカルでの確認方法

Python 3があれば、展開したフォルダーで以下を実行します。

```bash
cd shiwake-training
python3 -m http.server 8000
```

Windowsでは、環境に応じて次のコマンドを使います。

```powershell
cd shiwake-training
py -m http.server 8000
```

PCで `http://localhost:8000/` を開きます。停止は `Ctrl+C`。

- `index.html`のダブルクリック（`file://`）では、ES ModulesとService Workerが正常動作しません。
- Service WorkerはHTTPSまたはlocalhostで動きます。スマホからLAN内PCのHTTPアドレスを開く方法では、オフライン準備ができません。iPhoneではHTTPSのGitHub Pages URLを使ってください。
- サブディレクトリも確認したい場合、ひとつ上のフォルダーでHTTPサーバーを起動し、`http://localhost:8000/shiwake-training/` を開きます。
- 開発時、Service Workerが以前のコードを表示することがあります。変更後は後述のバージョン更新を行うか、**テスト用**ブラウザの開発者ツールで対象のService Workerを解除します。実際の学習データを消さないでください。

## 2. GitHubへのアップロード方法

### Web画面で行う場合

1. [GitHub](https://github.com/)でリポジトリを新規作成します。
2. 名前の例は `shiwake-training`。無料公開には**Public**を選びます。初期READMEを追加して作成すると、ファイルのアップロード画面へ進みやすくなります。
3. リポジトリの Code → Add file → Upload files を開きます。
4. 展開したフォルダーの中にあるファイルと `icons/`、`tests/` をアップロードします。ZIPファイル自体をアップロードしないでください。
5. `index.html`がリポジトリの最上位にあることを確認し、Commit changes。

必要な配置は次のとおりです。

| 場所 | 内容 |
|---|---|
| `index.html` | 画面の土台・iPhone向けメタ情報 |
| `styles.css` | スマホ優先の画面・電卓・セーフエリア |
| `app.js` | 画面操作・出題・採点連携・PWA準備 |
| `core.js` | 採点・電卓・統計・苦手抽出 |
| `storage.js` | IndexedDB保存、localStorageフォールバック |
| `questions.js` | 独立した300問の問題データ |
| `manifest.json` | インストール情報・相対URL・アイコン |
| `service-worker.js` | 全学習ファイルの事前キャッシュ |
| `icons/` | 192/512px・maskable・Apple用アイコン・SVG原本 |
| `.nojekyll` | 静的ファイルをそのまま公開する指定 |
| `.gitignore` | 開発用依存物と履歴バックアップの除外 |
| `README.md` / `VALIDATION.md` | 利用手順と検証範囲 |
| `tests/` / `package.json` / `package-lock.json` | 開発者向けの再現可能なテスト |

`.nojekyll`がアップロードされなかった場合は、Add file → Create new fileで、名前 `.nojekyll` の空ファイルを追加できます。実行に必要なのはHTML・CSS・JS・Manifest・Service Worker・アイコンです。テスト関連ファイルはアプリ起動時には読み込みません。

## 3. GitHub Pages公開方法

1. リポジトリの Settings → Pages。
2. Build and deployment の Source を **Deploy from a branch** にする。
3. Branchを `main`、フォルダーを `/(root)` にする。
4. Saveを押し、公開処理を待つ。進行状況は Actions または Pages画面で確認できます。
5. Pages画面に表示された公開URLを開く。

URLの形は `https://ユーザー名.github.io/リポジトリ名/` です。末尾の `/` を含めたURLを使用してください。

すべてのアプリ資産、Manifestの `id` / `start_url` / `scope`、Service Worker登録は相対パスです。リポジトリ名をコードに埋め込む必要はありません。

**保存先は端末内です。** 公開サイトにアクセスしても、学習履歴がGitHubへ送信されることはありません。書き出したバックアップJSONをリポジトリへアップロードしないでください。

## 4. iPhoneへのインストール方法

現行Safariを推奨します。利用目安はiOS 17以降です。

1. 通信できる状態で公開URLを**Safari**で開く。
2. 画面上部の **「オフライン準備完了」** を待つ。
3. Safariの共有メニュー → **ホーム画面に追加**。
4. 「ウェブアプリとして開く」が表示される場合はオンにして、追加。
5. ホーム画面の「仕訳トレ」を開く。
6. このホーム画面アプリでも、オンラインのまま「オフライン準備完了」を確認する。

ホーム画面からは `standalone` で開く構成です。アイコン、Apple専用アイコン、画面端のセーフエリアを設定済みです。

Safariタブとホーム画面アプリで保存領域が分かれる場合があります。今後はホーム画面のアプリに統一して学習してください。既にSafari側で学習した場合は、JSON書き出し→ホーム画面側で読込みにより移行できます。

## 5. オフライン動作確認方法

公開後、実際のiPhoneで以下を確認してください。

1. ホーム画面からアプリをオンラインで起動し、**準備完了**を確認する。
2. レベルを「簿記論」に変え、1問回答する。
3. 機内モードをオンにし、Wi-Fiもオフであることを確認する。
4. アプリをアプリスイッチャーから終了する。
5. ホーム画面のアイコンから起動する。
6. レベルが維持され、問題を表示できることを確認する。
7. 電卓で `120000 × 0.7` → `84000` を計算し、金額へ反映する。
8. 借方・貸方の行を追加・削除し、回答・採点・解説・次の問題を確認する。
9. 学習記録を開く。アプリを再終了・再起動しても回答数が残ることを確認する。
10. 「間違えた問題」「苦手論点」を開き、復習できることを確認する。

初回起動前にオフラインにした場合は使えません。また、OSがWebサイトデータを削除した場合、空き容量不足、利用者がSafariデータを消した場合などには、再ダウンロードが必要になります。

### 更新時の動き

- ファイルはバージョン単位で事前保存し、学習中の新旧コード混在を避けます。
- 新版が用意できると「新しいバージョンがあります」を表示します。
- 「更新する」で回答途中の状態を保存してから切り替えます。
- コードまたは問題を変更したときは、**必ず `service-worker.js` 冒頭の `VERSION` を変更**してください。例：`v1.0.0` → `v1.0.1`。
- ファイルを追加した場合は、Service Workerの `ASSETS` に追加してください。
- 更新時に履歴のIndexedDBを消す処理はありません。キャッシュ削除は自分の公開パスの旧版だけが対象です。

## 6. 問題を追加する方法

`questions.js`の `QUESTIONS` 配列へ、次のようなオブジェクトを追加します。`b()` / `z()` の補助関数を使わず、この形式でそのまま追加できます。

```js
{
  id: 'B071',                   // 一意・不変のID（使用済みの最大はB070・Z230）
  level: 'bookkeeping2',        // または zeirishi_boki
  difficulty: 2,              // 1〜3
  category: '現金預金',
  prompt: '普通預金から現金30,000円を引き出した。',
  debit: [{ account: '現金', amount: 30000 }],
  credit: [{ account: '普通預金', amount: 30000 }],
  explanation: '資産間の移動なので、現金が増え、普通預金が減る。',
  requiresCalculation: false,
  trap: '費用は発生していない。',
  distractors: ['支払手数料', '借入金']
}
```

- 借方・貸方は配列。複合仕訳は各配列に複数の行を記入します。
- 金額は正の整数、円単位、上限999,999,999,999円。正答は必ず貸借一致。
- 税金・処理方法・使用科目・丸め方法・処理範囲を明示し、正答が一意になるようにしてください。
- 異なる論点で同じ名前を使うとカテゴリーが合算されるので、表記を統一します。
- 追加した正答科目と `distractors` は候補に自動反映されます。
- 明確な同義語のみ `ACCOUNT_ALIASES` へ追加できます。「現金」と「普通預金」など意味の異なる科目は統合しません。
- 既存IDを別の問題に転用しないでください。学習履歴はIDに紐づきます。
- 問題追加後、テスト・会計内容の確認を行い、`BANK_VERSION` とService Workerの `VERSION` を更新します。
- 将来のレベル追加は `LEVELS` に表示名を追加し、対応する `level` の問題を追加してください。レベル選択・履歴・採点はそのレベル文字列に対応します。

## 出題と採点

| モード | 挙動 |
|---|---|
| ランダム10問 | 選択レベルから重複なしで10問 |
| ランダム30問 | 選択レベルから重複なしで30問 |
| エンドレス | 選択レベルの全問を一巡ごとにシャッフル。周回境界の連続同一問題も回避 |
| 間違えた問題だけ | 直近回答が不正解の問題を一巡。正解後は次回の対象から外れる |
| 苦手論点だけ | 正答率・直近の誤答・平均回答時間から抽出した問題を一巡 |

対象が10/30問未満の場合は、利用可能な問題数で一巡します。レビュー対象が0問の場合は、その旨を表示します。

苦手判定は、選択レベル範囲内のカテゴリー正答率80％未満、またはカテゴリー平均回答時間30秒超。加えて直近誤答、2回答以上で正答率80％未満、問題平均30秒超（計算問題45秒超）も対象です。カテゴリーが苦手なら同カテゴリーの未回答問題も出します。

採点は借方・貸方を別々に、科目ごとの金額合計で比較します。入力順は不問。同じ側の同一科目は合算し、完全な空行は無視します。借方と貸方を相殺した答案は同一とはみなしません。「わからない」は誤答として記録します。

## 電卓

- `0〜9`、`00`、`000`、小数点、`＋－×÷＝`、`C`、`⌫` を収録。
- 四則演算の通常の優先順位（乗除を先に計算）を使います。
- `＝` の後に演算子を押すと、直前の結果から続けて計算します。例：`2＋3＝×4＝` は20。
- 元の式と結果を同時表示し、「金額に反映」で選択した借方／貸方の行へ転記します。
- 金額欄はボタンなので、標準の数字キーボードを表示しません。
- 円未満が残る場合、四捨五入・切り捨て・切り上げを**問題の指示どおり**選びます。表示は小数点以下最大8桁ですが、演算はBigInt分数による計算で端数判定します。
- ゼロ除算・上限超過・未完成の式は転記できません。0円・負数も仕訳金額に転記できません。
- `eval()` や `new Function()` は使用していません。

## 学習履歴・保存

- 各回答について、問題ID・科目と金額・正誤・時刻・回答時間・レベル・カテゴリーを保存します。
- その回答ログから問題別回数、正解／不正解回数、最終日時、平均回答時間、連続正解、レベル別／カテゴリー別正答率を計算します。
- 「今日」「直近7日」は端末の現地時間。直近7日は今日を含む7暦日です。
- アプリが非表示の間と中断中は計測停止。未回答問題の下書き・経過時間も保存します。
- 主保存先はIndexedDB。利用できない環境ではlocalStorageを使用し、その後も同じ保存先を継続します。
- 保存キーは公開パス別。GitHub Pages上の別リポジトリと履歴やキャッシュが混ざらない設計です。
- 同時に複数タブで同じトレーニングを進める使い方は避けてください。
- クラウド同期はありません。容量不足・ブラウザデータ削除・OSによる消去の可能性に備え、使い方画面から定期的にJSONで書き出してください。
- JSON復元は既存履歴と統合し、回答IDが同一なら二重計上しません。初期版は現在の問題セットに存在しないIDを含むバックアップを拒否するため、問題IDは原則削除しないでください。

## 開発者向けテスト

実行用コードはVanilla JavaScriptです。以下のnpm依存は**テスト専用**で、公開サイトからは読み込みません。

Node.js 24で検証しています。

```bash
npm ci
npm test
```

依存物の導入なしで、採点・電卓・問題データ・Service Workerのロジックだけを検証する場合：

```bash
node --test tests/core.test.js tests/sw.test.js
```

詳細な検証範囲と実機未確認項目は [VALIDATION.md](./VALIDATION.md) を参照してください。

## 内容の前提と参考資料
